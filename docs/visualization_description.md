# Визуализация пайплайна и отличия от блок-схемы алгоритма

## Использованный способ визуализации

Для визуализации пайплайна использованы **встроенные средства Dagster**:

1. **Dagster UI (Asset Graph)** — интерактивный граф зависимостей между assets, доступный через `dagster dev`.
2. **Экспорт в PNG** — скрипт `scripts/generate_dag_visualization.py` строит DAG на основе `AssetGraph` и сохраняет изображение через Graphviz.

Оба способа автоматически строят граф из кода пайплайна — ручная отрисовка блок-схемы не требуется.

## Структура DAG в Dagster

Пайплайн реализован как цепочка **assets** (материализуемых артефактов данных):

```
fastqc_report
reference_index → alignment_sam → alignment_bam → flagstat_report → mapping_qc_summary → variant_calling
```

Параллельно существует тестовый пайплайн Hello World:

```
hello_world_message → hello_world_greeting
```

## Отличия визуализации Dagster от блок-схемы алгоритма

| Аспект | Блок-схема (слайд 5 задания) | DAG Dagster |
|--------|------------------------------|-------------|
| **Условные переходы** | Явная развилка «%mapped > 90%» → OK / not OK | Условие реализовано в коде asset `variant_calling`; на графе зависимости линейные, ветвление не отображается как отдельный ромб |
| **Тип узлов** | Процедуры (FastQC, minimap2, samtools…) | **Assets** — именованные выходные данные (BAM, flagstat, VCF) |
| **Параллельность** | FastQC и индексация могут идти параллельно, но на схеме не всегда явно | На графе Dagster `fastqc_report` и `reference_index` — независимые ветки |
| **Повторное использование** | Не показано | Dagster отслеживает, какие assets уже материализованы, и пропускает их при повторном запуске |
| **Метаданные** | Только текстовый вывод OK/not OK | К каждому asset добавляются метаданные (% mapped, пути к файлам, статус) |
| **Ориентация** | Вертикальный поток сверху вниз | Граф Dagster — горизонтальный DAG слева направо (при экспорте в PNG) |

## Вывод

Визуализация Dagster отражает **зависимости данных** (какой asset от какого результата строится), а не полную логику ветвления алгоритма. Блок-схема из задания описывает **процедурный алгоритм с условием**, тогда как Dagster DAG показывает **граф материализации артефактов** — это data-oriented представление пайплайна, характерное для фреймворков оркестрации данных (DS/ML pipelines).
